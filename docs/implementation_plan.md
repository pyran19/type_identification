# 実装計画

## 目的
18種類の防御タイプ候補に対して、攻撃技のタイプと被ダメージ倍率の組み合わせだけを観測したとき、候補を一意に識別するのに必要な最小攻撃タイプ数を求める。

今回の前提は以下の通り。
- 防御側ポケモンは単タイプのみを持つ。
- 攻撃側の威力・一致補正・急所・特性・持ち物・天候などは考慮しない。
- 観測値は「攻撃タイプごとの相性倍率」のみとする。

## 進め方
1. タイプ相性表をプログラム内データとして定義する。
2. ある攻撃タイプ集合に対して、各防御タイプの倍率シグネチャを生成する。
3. すべての防御タイプのシグネチャが相異なるかを判定する。
4. 攻撃タイプ数 1 個から順に全組み合わせを探索し、最初に識別可能になった個数を最小値として採用する。
5. 最小個数を達成する攻撃タイプ集合を列挙する。
6. 例示ケースと全体探索結果をテストで固定する。

## 想定成果物
- ライブラリ関数: 最小個数探索、シグネチャ生成、識別可否判定。
- CLI: 実行すると最小個数と該当する攻撃タイプ集合を表示。
- README: 問題設定、アルゴリズム、使い方、出力例を説明。
- pytest: 基本例と全探索結果を検証。

## アルゴリズム選定理由
攻撃タイプ数は18種類しかないため、全部分集合の総数は `2^18 - 1 = 262143` であり、総当たり探索でも十分に扱える。したがって、実装を単純かつ検証しやすい全探索を採用する。
